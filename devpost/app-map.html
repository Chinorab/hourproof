HourProof app map

A take home guide to where things live in this proof of concept. Snapshot of commit 13c05d0; the code can drift after this.

What the app does

A gig worker uploads a weekly earnings screenshot. Claude reads the app name, dates, active hours and earnings. The person checks the values, and the month's totals are compared with the federal Medicaid work requirement: 80 active hours, or $580 earned after expenses. The test closer to its line becomes the big number. A one page summary can be printed or saved as PDF.

In the browser

All screens, the saved entries (localStorage), and all the math: proration, totals, gaps, days left.

One server route

/api/extract sends the shrunk screenshot to the Claude API with a strict schema and returns the fields. It keeps the API key secret and stores nothing.

One action, end to end: a screenshot moves the big number

Reference route (3 stops)

A route to follow in your editor. Search for the names in code to land on the right spot.

  1. Read: the phone prepares the screenshot

    components/UploadPanel.tsx, function handleFile, calls readScreenshot in lib/read.ts. That shrinks the image to 2000 px JPEG (lib/image.ts, shrinkImage) and posts it to /api/extract with a 60 second limit. The reading state and Cancel live here too.

  2. Extract: Claude reads it into a fixed shape

    app/api/extract/route.ts, POST, checks type and size, then calls extractEarnings in lib/extract.ts. ExtractionSchema makes every field nullable so a value Claude cannot see comes back as null, not a guess. instructions() holds the reading rules: active time over online time, infer a missing year, app name only.

  3. Count: review, save, compare with the thresholds

    components/AddFlow.tsx, submit, checks for a duplicate week and saves through saveEntries in lib/storage.ts. app/page.tsx rerenders: monthTotals, dominantTest and testStatus in lib/month.ts compute the month, and DominantProgress in components/TestProgress.tsx shows the big number.

To change this, start here

The 80 hour or $580 thresholds

lib/thresholds.ts. The only place the numbers live, with their CMS sources. The minimum wage figure drives the income threshold.

What Claude reads from a screenshot

lib/extract.ts: add a field to ExtractionSchema, describe it in instructions(), then map it in extractEarnings and draftFromExtracted (components/ReviewCard.tsx). Re-run the sample images to check.

How a week across two months is counted

lib/month.ts, overlapDays and monthTotals. Covered by lib/month.test.ts; run npm test after a change.

Wording on the main screen and the summary

app/page.tsx, components/TestProgress.tsx (gap and met labels), components/HonestyNote.tsx, components/MonthlySummary.tsx. Keep the rule: never an eligibility claim.

The sample screenshots

HTML in scripts/make-samples/, rendered with npm run samples into public/samples/. lib/sample.ts reads them through the real route and moves their dates to a recent week.

A practice to reuse

Ask the model for an exact shape, let "unknown" be a valid answer, and check it against varied fixtures.

In this project the extraction schema (lib/extract.ts, ExtractionSchema) makes every field nullable, and three sample screenshots with deliberately different layouts plus one non earnings image live in public/samples/. Running them through /api/extract showed the reading was right on hours, dates and totals, and caught one miss: the app name came back with the screen title ("Sample Courier Earnings"). One added line in instructions() fixed it, confirmed by re-running the same images.

On another project that reads documents or images, write the schema first, include a fixture that should be rejected, and re-run the same fixtures after every prompt change.
